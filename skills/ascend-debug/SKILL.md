# 精度与编译问题诊断

先定位失败阶段，保留第一个有意义的诊断和有效命令。导入/资源等待、解析/验证、pass、链接、launcher/ABI、设备执行、数值比较、采集解析和清退是不同阶段；最后的 ERR99999 或非零退出码通常不够归因。

需要解释 API、错误码或寻找同症参考时，用 [知识检索](../ascend-knowledge/SKILL.md) 查具体标识符或脱敏症状，再核对当前调用与最小复现。只发送必要公开问题，不把完整私有日志自动上传为检索条件。

## 选择最小可区分实验

确认实际源码、工具、输入、特化、binary和环境；用源码/已留产物先排查身份误用。若目标尚未启动，不先研究设备算法或 SSBUF 等待环。

先保留几个不同层次的解释并选择廉价区分。允许临时强制分支、缩减 shape、限单轮 while或去掉计算，但注明其破坏的语义和仍保留的通信。单轮通过只缩小到复用/后续代次问题，不能直接证明 while 机制有错。

具体模式见 [诊断参考](references/diagnostic-patterns.md)。候选保留时恢复数值与工作量，并验证原复现、受影响边界和必要回归；不要求诊断中每个破坏性微例先通过完整精度。

## 精度路径

保存 seed、完整输入或可复现生成法，报告 shape/dtype/stride、布局和约定。确定参考语义、累加/舍入/饱和、NaN/Inf/符号零及允许误差；低精度格式的独立参考本身也可能有缺口。

同时观察绝对/相对误差、非有限值、mismatch坐标和分布，不只给一个 allclose。需要按位语义时单独核对，避免相对误差在接近零处失真。容差随目标语义确定，不为“跑通”临时放宽。

定位首个错误中间值或 tile：按误差模式区分索引/尾块、layout、初始化/累加、转换、并行写、缓冲区复用和越界。输出 guard、未写区和输入完整性可排除部分解释，但不单独证明任意内存正确性。

## 编译与启动路径

分清 unsupported feature/主动fallback、坏IR、工具格式不兼容、真实 pass错误和环境/资源问题。记录请求选项和最终有效 metadata；编译成功但回退的路径不是预期优化已生效。

跨 LLVM/NPU-IR/CCE 时先做当前阶段的解析或序列化小回环。保留完整模块及必要函数/类型；同一个工具能写出某版本 bytecode，不代表本组合能读回。不要仅删除未知属性或按错误词替换 op，先确认语义及版本合同。

编译器修复落在负责类型、规划、转换或后端驱动的正确层。手改 IR可诊断；需要泛化的修复按结构/类型/effects实现，不匹配固定 SSA名、地址、kernel名或 flag 来掩盖错误。独立 worktree/工具副本避免影响并行任务。

设备查询或普通 Python 启动阻塞时避免重复制造探针；区分用户态异常、D态等待和进程已退出。取消请求不等于内存或设备资源已释放。只处理本任务有权控制且身份核验过的执行树。

## 交付结论

写明现象、证据、被排除解释、保留原因/未知、修复与验证范围。参考模型修正、局部绕过、根因修复、完整流水回归和真机验收不能互相替代。已有准确基线也失败时，逐项比较失败集合，不把数量差直接当新回归。
