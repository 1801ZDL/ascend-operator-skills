# 分层诊断参考

## 先按故障所在阶段缩小问题

| 现象 | 优先区分 |
|---|---|
| 命令没日志、Python未进入 | 自有进程是否启动、资源等待/路径/权限/运行时导入；不是已知编译失败 |
| IR parse/verify报错 | stage与dialect、类型/属性、完整模块、工具版本和bytecode边界 |
| pass失败或主动fallback | 原因日志、请求选项、最终metadata；fallback可能是设计支持边界 |
| undefined symbol/链接失败 | producer/consumer库、宏传递、gitlink、实际链接参数；不是先补运行时算法 |
| launch/初始化失败 | ABI、设备映射、目标/metadata、权限、驱动边界；管理查询成功不能替代运行 |
| 输出错误或超时 | 首个错误tile、布局/索引/累加、别名/越界、同步与资源代次 |
| 结果正确但工具signal/解析失败 | 原始数据完整性、子进程、parser和清退，不自动重复目标 |

保留每个分类的未确定项。当前无设备需求时，不为了填表发起真实设备查询或导入重型后端。

## 精度常见切口

- 周期性、某些行列或尾块错：索引、stride、mask、padding、布局和实际输出覆盖。
- 首tile对、复用后错：初始化、积累模式、slot/代次、读完归还、跨任务输出缓冲。
- FP32参考近似但低精度溢出错：输入位型、转换路径、round/saturate枚举、格式定义和参考是否完整。
- NaN/Inf、±0或tie差异：单独定义语义，检查转换、reduce/min/max及异常值；相同LLVM intrinsic不自动证明CPU参考适用。
- 只在完整grid错：角色/peer、物理映射、共享状态与写者，不能只重复单block精度。

局部中间值观测会改变寄存器活跃、同步与性能。先用已有结果或小缓冲保存必要点，确认观测未改变被诊断的路径；观测版成功不代表原版已修复。

## 编译器与格式

“同一份LLVM”仍需匹配类型注册、intrinsic、DataLayout/目标feature与链接库。类型适配优先以当前底层`.ll`契约和最小编译例贯通；不要因同位宽把不同浮点格式的转换视为恒等。

宏开关要分别检查C++预处理、生成配置头、TableGen/模板及链接对象。旧构建里手工`-D`可能掩盖CMake传递缺口；需要核宏传播时用没有该手工值的新配置。只做语法通过不等于链接和运行通过。

LLVM22/旧NPU-IR组合曾需要bytecode v4；一些本地组合v6甚至同tool回环失败。它是定位线索，不是全局规定。先用真实小IR比较写/读、generic文本和两端解析，明确哪段格式变化且确认语义；不将“换一个版本能parse”当完成lowering或数值证明。

新旧`bufferization.to_memref`/`to_buffer`与`to_tensor`打印格式可能不同。按当前schema和语义处理，不能因拼写相似就批量替换。旧工具打印后丢失新属性、再让新工具解析也可能失败；处理边界优先统一配套或保留准确的格式适配，不在此过程中夹带优化。

debug行号问题分别检查`debug_info`、`line_info`、ELF段及addr2line映射。调试符号可与设备assert/额外观测无关；开启TRITON_DEBUG未必是正确最小修复，且可能改变被测行为。纯SIMT走不同stage时检查自己的生成命令。

## 同步与挂起

缩减循环可以定位首次进入与复用，但需保留对应peer供给、种子和drain。若删掉另一端SET才挂起，这个微例不代表原算法死锁。用不同合法顺序、有限代次和是否保留TRY等最小对照区分条件、counter取样与队列环。

通知身份带接收角色/peer/模式/ID，按每一代追踪提交、SET可见、WAIT领取、读/写和归还。counter“可见为正”与软件“允许提交新一代”不是同一契约；也不能把搬到S后一个输入跑通当作原门条件任意情况下正确。

对仍未证明的可见性或时序，形成具体可回答的问题：稳定counter、没有其他消费者/新SET、精确WAIT/TRY机器形式及所问的排序边界。不要用典型模拟延迟补成架构保证。
