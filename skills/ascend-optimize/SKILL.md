# Ascend 性能分析与优化

以用户关心的有用输出完工时间和可维护实现为目标。计算核利用率用于归因，不要求所有核永远满载，也不以采用某条指令、增加 buffer 或框架层数作为成果。

## 找到可改变的瓶颈

绑定强基线、输入、实际工作量与计时窗口；已有性能证据不足时按 [性能测试](../ascend-benchmark/SKILL.md)补最小对照，而不是直接扩矩阵。使用当前原始数据，不默认重跑历史捕获。

从启动、稳态、收尾区分控制发射、有效算术、搬运、依赖、容量反压与并行失衡。1C+2V结构下，分别看 Cube及两V的有用工作和共同完工；具体拓扑仍由目标确定。对重叠事件取区间并集，不能把并行时长相加或将 VF包络当纯算术忙碌。

沿大空档追问：有没有独立合法任务？输入真正到位了吗？输出/临时buffer是否空闲？指令已提交还是未发出？解除当前前驱能否提前最终输出？长WAIT、近邻copy、静态spill计数或PMU单列只能定位线索，根因和可回收时长需要额外依据。

## 选择手段

| 观察到的约束 | 可区分的方向 |
|---|---|
| 冗余工作、tile/算法不合适 | 减少实际操作、合并阶段、改变tile或算法 |
| 布局/向量化/带宽成本 | layout、访存合并、数据复用、精度表示 |
| 可独立的 load/copy 发得晚 | 计算/访存拆分，独立准备进度和所有权 |
| buffer容量或过长生命周期 | 按边容量、缩短最后读生命周期；核实际物理布局成本 |
| 一个V准备而另一个有余量 | 按合法任务分工，核私有状态、metadata及结果写者 |
| 合法任务就绪次序随运行态变化 | 动态选序或ready提示，比较强静态/软件调度对照 |
| 额外scalar和调度成本抵消收益 | 缩减控制工作或关闭该策略，不强行保留动态化 |

上述是可选方向，不是每个算子都应实现的阶段。CV/IR改写的成立条件见 [CV与IR参考](references/cv-and-ir.md)。对纯SIMT或其他流水结构按其真实瓶颈调整。

缺少接口约束或参考实现时，可用 [知识检索](../ascend-knowledge/SKILL.md) 查具体优化手法、算子或布局。将远程方法作为候选，核对适用版本、资源和依赖；最终由当前功能和同条件性能决定保留。

## 实验与保留候选

每轮选择会改变判断的小干预；确认lowering确实保留改动、最终指令有真实工作。前端更简洁可能产生相同ELF；重复copy/helper可能被消除。没有命中干预就先修实验，不据此宣布硬件无优化空间。

诊断允许不保持数值；保留候选须恢复功能并核受影响的布局、数据/资源代次、ABI、边界及完整工作量。静态分析估计上限是线索；固定顺序无收益不自动排除跨状态动态收益，反之单输入的固定改序也不证明动态策略有效。

变更进入可泛化的 DSL/编译器层时依据当前项目约定选择位置，识别 SSA、类型、控制及effects，不按本次case名字打补丁。不支持结构保持原行为或明确拒绝；资源预算计算覆盖 backing、padding、转换和后端额外物化，而非只数逻辑alloc。

以同条件性能决定保留策略；报告额外内存/flags/scalar开销和收益范围。负结果关闭实际验证的假设，不泛化成“该指令永远无用”。几轮未增加信息就回看前提；无需继续扩大形状或采样来制造正结果。

可复用经验写入场景扩展，标明证据及反例；当前任务的结果保存在项目短状态，不把整轮研究历史灌入公共skill。
