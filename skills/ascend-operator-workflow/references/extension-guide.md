# 开放式扩展和经验维护

## 选择最小扩展层

| 内容 | 放置位置 |
|---|---|
| 个人服务器、路径、执行器、CANN/卡映射 | 本地profile或任务目录；不改公共默认 |
| 某算子族、dtype、目标或控制结构的规则 | `extensions/<场景名>/SCENARIO.md`，使用场景模板 |
| 稳定且重复的离线整理/执行动作 | 相应skill的`scripts/`，参数化并验证实际行为 |
| 适用面充分、不同任务复现的经验 | 对应专项正文或references；更新原条而非叠加重复禁令 |
| 仍在研究的猜想/失败/下一步 | 本项目状态与实验索引；不急于提升为全局skill |

`extensions/`仅在确有场景时创建；不预建空目录。其他人的扩展可保留独立维护者和版本，不要求有本机实验树或同一Agent平台。

## 场景的最低可用信息

从 [模板](../assets/templates/scenario.md) 复制到当前项目或技能包的扩展目录，按需要删字段：

- 要解决什么、已观察到什么，适用的kernel结构、硬件/工具/输入或行为前提。
- 状态：草案、试用、限定范围采用、撤销。区分架构规范、源码事实、实测、推断及未知。
- 推荐动作、何时不适用、必要依赖/资源与已有执行授权边界。
- 支撑与反例、替代方案、撤销或扩大验证范围的信号。
- 本轮修改了哪项判断、观测成本或副作用、下次复查条件。

不要将“某次固定flag=3”“特定18参ABI”“该服务器有8卡”“本次2路编译”提升为通用条件。函数名白名单、源码路径和CLI参数如果是既有接口契约，应说明契约来源与版本，不包装成语义泛化。

## 匹配、冲突与授权

按任务实际情况选相关扩展，不默认加载所有扩展。当前用户指令和适用项目约定优先；扩展之间冲突时缩小范围、保存分歧或做最小对照，不让更新日期自动替代证据。

经验可以建议不同方法，但不能新增启动设备/外部模型、读取其他用户配置、安装包、推送、服务部署或取消他人作业的授权。使用已有任务授权继续正常工作；不凭技能模板重复索要已给出的授权。

## 验证与发布

改文档检查链接、范围和触发描述即可；脚本检查正常路径及能改变结论的失败/边界。接口或危险执行能力变更按实际风险验证，不要求每次经验补充重跑设备矩阵。

可用实际任务、脱敏原始结果或纯CPU场景演练。说明测试覆盖何种行为：元数据验证不是技能决策全对，CPU mock不是NPU验收，独立review也不代替实际结果。没有相应授权时不为“测试skill”新增并行Agent、付费模型或真实采集。

修订已有经验时保留原证据索引或撤销理由，不复制私有聊天、凭据、完整ISA、原始输入和其他租户信息。分发整个技能包以保留相邻引用；只分发专项时一并带上其引用资源，或在本地明确替换入口。外部知识提供方的接入独立维护，例如 [Ascend KG](../../ascend-knowledge/references/kg-tools-integration.md)；不把远程执行流程原样提升为所有任务的默认。
