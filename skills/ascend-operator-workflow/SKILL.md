# Ascend 算子工作流总入口

按用户要完成的结果选择当前阶段，可以直接进入诊断或优化，不强制完整流水。方法用于帮助决策，不替代用户目标，也不强制采用 TRY_WAIT、动态调度或某一种框架。

## 先确定本轮问题

结合已有材料确认算子/测试入口、输入及语义、目标硬件、用户关心的输出，以及目前卡在哪一层。缺少条件时继续不依赖该条件的工作，只在会影响决策时澄清。

新任务与续接任务分开：续接先读项目短状态；新任务只复用相关背景，不恢复历史聊天和旧待办。阶段性覆盖短状态，保留关键证据索引；历史记录中的“运行中”需与执行端事实区分。

知识检索按实际缺口触发；KG 返回的文档或 skill 用于评估方法与来源，不自动替代当前工作流、资源准入或执行授权。离线/无 Key 时继续使用本地证据，不以安装外部服务作为每个任务的前置步骤。

## 实验与资源

每轮说明待区分的解释、最小干预、预期观测及结果如何改变下一步。诊断可以有意破坏计算或限制循环；保留候选再恢复数值语义并补受影响边界。若连续实验不能区分解释，回查入口、测量或更早前提，不只增加实现复杂度。

按实际阶段管理 CPU、RAM、设备、IO、临时空间、墙钟和必要的模型调用成本。构建并发不等于任务树资源上限；可用 NPU 不代表公共父级 RAM 有余量。沿用本任务已有授权和预算，不默认改共享安装、扩大公共额度或取消他人任务。只读分析不为走流程发起设备探测。

一次任务可以只产生“排除了一个解释”或“实验无效”。区分未执行、启动失败、编译失败、目标完成、数值结果、解析结果、异常退出和资源清退；原因不清楚就保留未知。目标已完成且原始数据完整时，优先评估离线恢复，不盲目重发。

## 阶段产出

规模按任务决定：一个小修复可只记录问题、改动、检查和限制；较长研究保存当前状态、输入/工具/二进制身份、原始结果和结论依据。参考 [状态模板](assets/templates/task-state.md) 与 [证据模板](assets/templates/evidence.json)，不要求套用固定文件名或 schema。

从本轮变更决定验证范围：布局看实际布局与读写，buffer/同步看代次和完整读者，控制流看零工作/首次复用/退出，ABI 看实际参数与 launcher。没有新覆盖或性能信号时停止扩大纯性能矩阵；必要功能边界仍保留。

报告实际成果及范围：静态分析、编译、局部/完整仿真、设备功能、设备性能分别注明。只运行了旧 binary、CPU 模拟或部分 grid 时，不能扩大成新源码实机验收。

## 开放式维护

新增场景按 [扩展约定](references/extension-guide.md) 和 [场景模板](assets/templates/scenario.md) 保存；具体形状、flag、地址、硬件及工具限制留在场景中。记录实证、反例和调整原因，允许修改或撤销旧默认；不为每轮对话生成新规章。此技能不自行授权启动多个 Agent、外部模型或常驻任务。
