# 本地工程 profile：在自己的项目中维护

公共技能不预设服务器账号、仓库路径、Conda 环境、设备编号或安装版本。新任务先从用户给出的入口和已有项目说明定位；确需反复使用时，在自己的项目里维护一个简短 profile，不将个人路径提交到公共技能仓库。

可按需要采用下表，未核对项留为未知：

| 信息 | 本任务的实际值 | 如何核对 |
|---|---|---|
| workspace 与算子源码 | 自行填写 | 测试 import / wrapper / JIT 源文件 |
| Python 与依赖 | 自行填写 | 当前解释器与包 metadata；实际加载另核 |
| Triton-Ascend / NPU-IR / LLVM / CCE | 自行填写 | 实际命令、提交、文件哈希和版本 |
| CANN 根与目标芯片 | 自行填写 | 本任务环境及 metadata，不修改公共链接 |
| build / override / cache / 输出目录 | 自行填写 | 当前 CLI 与写权限，优先任务独立目录 |
| 可复用的 LLVM/MLIR 构建或安装前缀 | 自行填写 | 路径、构建时 LLVM SHA、目标与配置、可用工具及证据；联合构建另记绑定的 NPU-IR 工作树 |
| 设备与资源预算 | 自行填写 | 当前已有分配、物理/逻辑映射及预算 |
| 原始结果和短状态 | 自行填写 | 当前任务索引；旧待办不自动续接 |

profile 记录核对日期和适用范围。旧环境可用于重放，但不能将其版本、设备健康或运行状态当成当前事实。读取 profile 不意味着激活环境、启动 Docker、查询 NPU 或执行其中的历史脚本。

只收集当前任务需要的信息，不读取其他人的环境或凭据。个人 profile 放在项目私有/忽略目录，例如项目自己的 `.local/`；分享前保留必要字段即可。没有 profile 不阻塞普通源码阅读或离线分析。
